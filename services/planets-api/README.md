# Индекс обитаемости экзопланет

Технический PoC для хакатона на .NET 10. Берёт подтверждённые планеты из таблицы `pscomppars` NASA Exoplanet Archive, вычисляет приближённый балл перспективности и показывает десять отдельных функций: рейтинг, карту неба, «паспорт мира», истории, сравнение с HWC, 3D-схему, процедурный мир, учебный эксперимент с орбитой, параметры и дополнительные наблюдения. Вкладки позволяют оценить каждую функцию отдельно перед выбором состава итогового приложения.

## Запуск

Нужен .NET SDK 10. Из корня проекта:

```bash
dotnet run --project Planets.Api --no-launch-profile --urls http://localhost:5057
```

Откройте [http://localhost:5057](http://localhost:5057): фронтенд и API работают на одном адресе, отдельная сборка JavaScript не нужна.

Или запустите в Docker из корня проекта:

```bash
docker compose up --build
```

Приложение будет доступно по тому же адресу. Для Docker нужен работающий Docker Engine. Снимки NASA и HWC сохраняются в именованном томе `catalog-data` и переживают пересоздание контейнера. Если порт 5057 уже занят локальным `dotnet run`, остановите его перед запуском контейнера.

Выберите планету над вкладками. Выбор сохраняется при переходе между функциями, а вкладку можно открыть напрямую через адрес вида `/#scene` или `/#observations`. В начале каждой вкладки описаны источник данных, расчёт и ограничения. Сравнение с HWC загружается при первом открытии его вкладки; запросы к Gaia, MAST/TESS и NASA spectra выполняются при открытии «Наблюдений».

При запуске сервис читает последний успешный снимок из `Planets.Api/data/nasa-planets.json`, затем обновляет его из NASA. Повторная загрузка происходит каждые 6 часов. Файл снимка создаётся автоматически и не попадает в Git. Если NASA недоступна, сервис продолжает отдавать последний снимок; до первой успешной загрузки `/api/candidates` отвечает `503`.

## Эндпоинты

- `GET /api/status` — готовность, время загрузки и количество кандидатов.
- `GET /api/candidates?limit=50&zone=all` — рейтинг. `limit` от 1 до 1000; `zone=conservative` или `zone=optimistic` оставляет только соответствующую группу.
- `GET /api/candidates/{name}` — карточка кандидата; пробелы и специальные символы имени нужно URL-кодировать.
- `GET /api/candidates/{name}/sources` — дополнительные данные Gaia, MAST/TESS и сведения о спектрах; для каждого источника отдельно указан `status`: `available`, `not_found`, `missing_id` или `unavailable`.
- `GET /api/hwc` — доступность, дата загрузки и потенциально обитаемые миры HWC для сравнения; при недоступности сайта отдаётся последний локальный снимок.
- `GET /api/methodology` — правила отбора и расчёта, веса, пороги, таблица границ зоны Kopparapu через 100 K и история версий.
- `GET /api/planets` — все подтверждённые планеты снимка в компактном виде: параметры для графиков, класс зоны и первый непройденный этап отбора (`exclusion`).

Ответ кандидата содержит балл и его три компонента, параметры планеты и звезды, координаты системы `rightAscensionDegrees` и `declinationDegrees` для карты, границы зоны обитаемости, `stability` с оценкой устойчивости места, орбитальные поля для интерактивной 3D-схемы, идентификаторы Gaia DR3 и TIC, показатели наблюдаемости TSM/ESM и `dataFlags` с оговорками к данным. Для отдельного фронтенда разрешены CORS-запросы `GET`.

Дополнительные источники загружаются при открытии вкладки «Наблюдения» и кэшируются на 15 минут. Gaia DR3 запрашивается через публичный TAP-сервис [ARI](https://gaia.ari.uni-heidelberg.de/tap/) по `gaia_dr3_id`: параллакс, температура, светимость и радиус звезды. [MAST](https://mast.stsci.edu/api/v0/) по `tic_id` сообщает число временных рядов TESS и секторы наблюдений. Таблица [NASA Atmospheric Spectroscopy](https://exoplanetarchive.ipac.caltech.edu/docs/atmospheres/atmospheres_home.html) сообщает тип, инструмент и публикацию доступных спектров. Это метаданные наблюдений, не извлечённые кривые блеска или спектральные точки. Данные Gaia пока не меняют балл: прямое смешивание оценок из каталогов без учёта погрешностей было бы некорректным.

## Балл v1

Это эвристика для **сортировки кандидатов**, а не вероятность существования жизни. Используются границы [Kopparapu et al. 2014](https://doi.org/10.1088/2041-8205/787/2/L29) для планеты массой 1 Земля:

- 50 баллов в консервативной зоне обитаемости, 25 — только в расширенной.
- До 35 баллов за радиус, близкий к земному. Если радиуса нет, используется масса.
- До 15 баллов за низкий эксцентриситет. Если он неизвестен или указан как предел, даются нейтральные 7,5 балла и добавляется флаг.

Отбор ограничивает температуру звезды диапазоном 2600–7200 K, радиус — 0,5–2,5 радиуса Земли, массу — 0,1–10 масс Земли. Если известны оба параметра, оба должны проходить фильтр. Спорные и околобинарные планеты исключаются, поскольку здесь применяется модель зоны обитаемости одной звезды. Если NASA не даёт поток излучения, он оценивается по светимости звезды и большой полуоси орбиты с отдельным флагом.

Поля `pscomppars` могут происходить из разных публикаций и часть значений рассчитана архивом; соответствующие пометки есть в `dataFlags`. Балл не следует называть ESI: для полноценного ESI нужна, в частности, оценка температуры поверхности, которой в каталоге нет. Первичный источник данных: [NASA TAP](https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html).

## Устойчивость рейтинга и 3D-схема

`stability` показывает диапазон балла и места от 10-го до 90-го процентиля, долю попаданий в топ-50 и долю прохождения отбора. Они получены из 160 воспроизводимых пересчётов всего каталога с опубликованными асимметричными погрешностями NASA. Интерфейс также показывает, для скольких входных полей погрешности известны. Это **не** вероятность жизни и не полная научная неопределённость: неизвестные ошибки фиксируются, корреляции и систематические эффекты не учитываются. Изменение потока в течение эксцентричной орбиты отдельно не моделируется.

В карточке можно вращать схему орбиты и зоны обитаемости, останавливать анимацию и переключать четыре варианта облика планеты. Орбита строится по параметрам NASA; размеры тел и скорость движения условны для читаемости. Палитры — художественные гипотезы: поверхность и цвет этих планет не измерены. Для Proxima Cen b есть ссылка на готовую [3D-модель NASA](https://science.nasa.gov/resource/proxima-b-3d-model/), тоже художественную.

Карта неба показывает **направление на звёздную систему**, а не положение планеты на орбите. Расстояние подписано отдельно. Учебный ползунок «передвинуть планету» показывает изменение потока по закону обратных квадратов; он не меняет рейтинг и не предсказывает температуру поверхности. [HWC](https://phl.upr.edu/hwc/data) используется только как сравнение: его список датирован 21 марта 2024 года, а оценки также в основном основаны на NASA. Его ESI — сходство с Землёй, не вероятность жизни.

Для восьми известных планет есть короткие истории с источником и отметкой, что пока неизвестно. Тексты вручную сверены с NASA, научными публикациями и материалами исследовательских групп; они не подгружаются автоматически и не влияют на рейтинг. [Русский список Википедии](https://ru.wikipedia.org/wiki/Список_потенциально_жизнепригодных_экзопланет) использовался только для поиска планет, а не как источник научных выводов.

Подробная карта источников и правила сопровождения проекта — в [AGENTS.md](AGENTS.md).

Во вкладке «Вообразить мир» сейчас доступны пять художественных обликов и ручной выбор варианта. Для финальной версии запланированы большая библиотека обликов, уникальный мир для каждой планеты и серверный кэш результата первой генерации. Сейчас такого кэша нет; Docker-том хранит только снимки каталогов.

## Версия 1.1 и устойчивость к сбоям источников

Версия балла 1.1 сохраняет веса и границы версии 1, но не использует как измерения значения, которые NASA публикует только как пределы (`st_tefflim`, `st_lumlim`, `pl_orbsmaxlim`). Таймаут NASA или HWC обрабатывается как недоступность источника: сервис отдаёт последний снимок, а до первого снимка повторяет загрузку через 1, 2, 4 … 30 минут. `GET /api/status` показывает `fromCache`, `lastAttemptAt`, `refreshError` и `nextAttemptAt`. Новый фронтенд портала живёт в `services/portal`; статический PoC в `wwwroot` сохранён как исходная реализация.

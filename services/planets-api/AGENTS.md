# Exo/Atlas — инструкции по проекту

## Назначение

Хакатонный каталог подтверждённых экзопланет, которые проходят предварительный отбор по зоне обитаемости и размеру. Балл — эвристика для сортировки, не ESI, не вероятность жизни и не подтверждение пригодности планеты для жизни. Интерфейс и тексты — на русском.

## Как запустить и проверить

```bash
dotnet run --project Planets.Api --no-launch-profile --urls http://localhost:5057
docker compose up --build
dotnet run --project tests/Planets.Checks --no-restore
node --check Planets.Api/wwwroot/app.js
node --check Planets.Api/wwwroot/scene.js
node --check Planets.Api/wwwroot/sky-map.js
node --check Planets.Api/wwwroot/stories.js
node --check Planets.Api/wwwroot/world-lab.js
```

.NET 10, ASP.NET Core Minimal API; фронтенд — статические HTML/CSS/JS в `Planets.Api/wwwroot`, без npm-сборки. Для вкладки процедурного мира используется локальная копия Three.js 0.187.0 (`wwwroot/vendor/three`, лицензия MIT в той же папке), поэтому показ не требует доступа к CDN. `Dockerfile` собирает приложение на SDK 10 и запускает на ASP.NET Runtime 10; `compose.yaml` публикует порт 5057 и сохраняет каталог `/app/data` в именованном томе `catalog-data`. На локальном запуске `Planets.Api/data/nasa-planets.json` и `Planets.Api/data/hwc.json` — снимки, создаваемые автоматически и не коммитящиеся; в контейнере те же файлы лежат в томе. При недоступности источника используется его последний снимок. Основные файлы: `CatalogService.cs` — NASA, `HwcService.cs` — сравнение с HWC, `Habitability.cs` — отбор и балл, `RankingUncertainty.cs` — модель погрешностей, `EnrichmentService.cs` — дополнительные источники, `Program.cs` — маршруты.

Перед публикацией истории проверяются по NASA, первичным работам или материалам авторов. |

На фронтенде дополнительные сетевые источники запрашиваются при открытии вкладки «Наблюдения» для выбранной планеты и кэшируются сервером на 15 минут. HWC загружается при первом открытии его вкладки. `/api/candidates/{name}/sources` возвращает для каждого источника `available`, `not_found`, `missing_id` или `unavailable`. Не путать `not_found` с отсутствием физического явления: это означает лишь отсутствие записи в запрошенном каталоге. Ошибка одного архива не должна останавливать основной рейтинг или остальные источники.

## Витрина функций

`wwwroot/index.html` и `app.js` показывают десять вкладок: рейтинг, карта неба, паспорт, истории, HWC, 3D-система, процедурный мир, учебный эксперимент, параметры и наблюдения. Это технический PoC для отбора функций финального продукта. Перед результатами каждой вкладки указаны её данные, расчёты и ограничения. Общий выбор планеты сохраняется при переключении вкладок; активная вкладка записывается в адрес после `#`. `initializeFeaturePanels()` переносит существующие блоки в соответствующие панели при загрузке страницы. Новую функцию добавлять в свою панель с кратким объяснением источника и границ интерпретации.

## Отбор, балл и устойчивость

Отбор `Habitability.Score`: звезда 2600–7200 K, поток внутри расширенной зоны, радиус 0,5–2,5 R⊕ и/или масса 0,1–10 M⊕, без спорного статуса и околобинарной орбиты. Если оба размера известны, оба должны пройти фильтр. Балл до 100: зона 50/25, размер до 35, эксцентриситет до 15. Неизвестный эксцентриситет получает 7,5 и флаг. Вычисленные архивом или оценённые нами значения помечаются `dataFlags`. TSM/ESM — показатели удобства спектроскопии, **не** обитаемости и не входят в балл.

`RankingUncertainty.Calculate` делает 160 воспроизводимых пересчётов с опубликованными асимметричными ошибками NASA. Для каждого известного поля выбирается отклонение по нормальному закону, с отдельной верхней/нижней погрешностью; пропуски фиксируются. Каждый раз пересчитывается весь каталог, включая возможных новых кандидатов. В API `stability` — 10-й и 90-й процентили балла и места **среди прошедших отбор**, доля попаданий в топ-50, доля прохождения отбора и число входных полей с указанной ошибкой. Эти проценты — чувствительность к **опубликованным** ошибкам при модели независимых измерений, не вероятность жизни и не полная научная неопределённость. Систематические ошибки, корреляции, разные публикации и неизвестные погрешности не моделируются.

## 3D-схема и внешний вид

`wwwroot/scene.js` рисует орбиту, звезду, планету и зону обитаемости на canvas с перспективной проекцией и вращением камеры. Форма орбиты зависит от большой полуоси и эксцентриситета NASA; движение следует эллипсу, но скорость анимации условная. Плоскость сцены не является восстановленной абсолютной ориентацией в пространстве. Если эксцентриситет неизвестен, используется круговая схема; если неизвестна большая полуось, масштаб орбиты условный. Размеры звезды и планеты увеличены относительно орбиты для читаемости.

Четыре переключаемые палитры — **художественные гипотезы**. Плотность позволяет только осторожно предположить широкий класс состава. Текущие источники не измеряют поверхность и её цвет для кандидатов. Не помечать палитру как «наблюдённую» по одной плотности, равновесной температуре или наличию спектра. Для наблюдённого цвета нужны отдельные измерения отражённого видимого света/альбедо с публикацией; сейчас такого источника в приложении нет.

`wwwroot/world-lab.js` — отдельная процедурная WebGL/Three.js-сцена. Пять выбираемых обликов (архипелаг, дюны, ледники, базальт, облака) создаются из смещённой треугольной сферы с цветами по высоте и шуму. Объёмные постройки и существа стоят на площадке, прикреплённой к сфере, и вращаются вместе с планетой. Камера управляется перетаскиванием, колесом/жестом масштабирования и кнопкой приближения к существам; вращение можно остановить. Скорость вращения условная, не является измеренным периодом планеты. Seed основан на имени планеты, выбранном облике и номере варианта, поэтому мир воспроизводим. Радиус, поток и температура звезды из NASA показаны отдельно; температура задаёт только условный оттенок освещения, а геометрия рельефа не является измерением. Ни один облик не выбирается по баллу или выдаётся за наблюдаемую поверхность. Вымышленная цивилизация скрыта до отдельного действия пользователя и не означает обнаружение жизни. Для сцены нужен WebGL 2.

План финального приложения: расширить библиотеку обликов, автоматически закрепить за каждой планетой уникальный облик и кэшировать результат первой генерации на сервере, чтобы все пользователи видели один и тот же мир при повторном открытии. Сейчас этого кэша нет: варианты выбираются вручную, а воспроизводимость обеспечивается seed в браузере. Не называть будущий кэш реализованной функцией PoC и не смешивать его с Docker-томом для снимков NASA/HWC.

`sky-map.js` показывает направления на звёздные системы по `ra` и `dec`, объединяя кандидатов у одной звезды. Подпись даёт расстояние в световых годах как перевод `sy_dist` из парсеков. Это плоская карта неба, а не положение планет на орбите и не 3D-карта с расстоянием в масштабе. Старый NASA-снимок может содержать `null` для координат до нового обновления.

«Паспорт мира» сравнивает период, получаемый поток и расстояние с Землёй. Период помечается как рассчитанный, если NASA указала `CALCULATED_VALUE`; остальные опубликованные периоды названы опубликованными измерениями. Поток излучения и перевод парсеков в световые годы помечены как вычисления. Ползунок учебного сценария меняет поток по формуле `S_new = S_catalog / factor²`, оставляя температуру звезды и границы зоны неизменными. Он не меняет реальный балл.

`wwwroot/stories.js` содержит вручную написанные короткие истории по точным именам NASA (`planet.name`). Карточка истории показывается только для планеты, которая прошла текущий отбор и есть в каталоге. Числовые параметры берутся из живого NASA API в «Паспорте мира»; не дублировать их в историях без необходимости, потому что исследования и каталог обновляются в разное время. Новые научные выводы добавлять с датой публикации, ссылкой и формулировкой уровня уверенности; гипотезы об океанах, атмосфере и жизни нельзя выдавать за наблюдения. Истории не меняют рейтинг.

## При изменениях

- Добавляя поле NASA, обновить TAP-запрос, `NasaPlanet`, `Candidate`, расчёт/интерфейс по необходимости и проверку. Старый снимок может не содержать новое поле до обновления сети; код обязан переносить `null`.
- Не смешивать оценки NASA и Gaia в балле без явной методики сопоставления и ошибок.
- Любое значение для цвета/состава помечать по уровню доказательности: наблюдение, вывод из измерений или художественный вариант.
- Не загружать сырые FITS-файлы на каждый просмотр карточки. Если добавляется график транзита, получать конкретный продукт наблюдения, обрабатывать качество точек и кэшировать результат отдельно.
- В интерфейсе данные внешних источников вставлять через `textContent`, а ссылки формировать из проверенных идентификаторов/библиографических кодов.
